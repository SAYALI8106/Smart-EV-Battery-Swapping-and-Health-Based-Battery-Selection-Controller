Problem Statement & Motivation

An EV battery swapping station holds several batteries, but some may be unavailable or unhealthy. The controller turns “available” and “healthy” into one valid bit per battery, checks the batteries one after another, and only generates an enable pulse for a battery that is valid.

Motivation: handing a customer a battery that is not ready or not healthy wastes time and is unsafe.

Novelty

Combines validity checking, round-robin digital selection, latching and active-LOW enable generation in a small educational logic design. It is a model, not a production EV technology.

Problem Understanding & Requirements

  • Four EV batteries are available.
  • Each battery has an Availability (A) and a Health (H) signal.
  • A battery is valid only when A = 1 and H = 1.
  • The controller checks batteries in round-robin order.
  • A MOD-4 counter gives four selection states.
  • The MUX checks the battery of the current counter state.
  • A D flip-flop stores the selected validity result.
  • A demultiplexer generates the battery-enable output.
  • The counter advances to the next battery only after the selected battery is valid and SWAP_DONE is pressed.
  • A decoder indicates which battery position is selected.
  • The design uses combinational logic, sequential logic and a clock.
Implemented behaviour: hold, not skip. The 74LS90 advances only when CNT_CLK = VALID · SWAP_DONE falls. If the battery being checked is invalid, CNT_CLK stays 0 and the counter waits on that battery; nothing skips it. Automatic skipping is a Future Enhancement.

Conceptual / Functional Block Diagram

Q is the latched validity of the battery that the counter was pointing at when the clock rose.

CNT_CLK = Q · SWAP_DONE  (7408 #2)

The 74LS90 counts on the falling edge of CNT_CLK, i.e. when SWAP_DONE is released while VALID = 1.

Enable path (as implemented)

1G̅ = Q̅   1C = CLKENn = NOT( CLK · Q · [S1S0 = n−1] )

74LS155 section 1 has an active-LOW enable 1G̅ and an active-HIGH data input 1C. Q̅ drives 1G̅ (enabled when Q = 1, i.e. valid) and the clock drives 1C, so the selected output goes LOW only while the clock is high. Hazard: if SWAP_DONE is released while CLK is high, the counter moves while the old Q = 1 is still stored, so the new battery's EN can go LOW until CLK falls. Release SWAP_DONE while CLK is low. A real build would clear the 74LS74 with a spare gate; not added here.

The K-map is used to simplify the Boolean logic for battery validity. One cell is 1, so V = A·H (one AND gate).

Cells hold variables, so no grouping is possible: Y keeps its four-term form. With the current switches:

Only one 1-cell: CNT_CLK = Q·SWAP_DONE, a single AND gate. This is the only control equation added; the counter advances only when VALID and SWAP_DONE are both 1.

State Table (hold until swap done)

Implemented behaviour: wait/hold, not skip. Next state = next battery only when VALID · SWAP_DONE; otherwise the state stays. The sequence B1 → B2 → B3 → B4 → B1 therefore happens only on completed swaps. A, H and the clock do not change the state directly.

State Diagram

Green = current state in the simulator. Forward arrows: CNT_CLK falls with VALID · SWAP_DONE. Loops: NOT(VALID · SWAP_DONE) → hold. No skip transitions exist.

Timing Diagram (5 clock cycles from RESET, current switches)

Each clock cycle is four slots. CLK↑ latches Q = VALID of the selected battery. SWAP_DONE is pressed in the second slot; if Q = 1, CNT_CLK = 1, and when SWAP_DONE is released CNT_CLK falls and the 74LS90 advances (Q0/Q1, S1/S0 and Y change). Q keeps the old value until the next CLK↑. If the battery is invalid (Q = 0), CNT_CLK stays 0 and the counter holds even if SWAP_DONE is pressed. EN rows are LOW (shaded) only while CLK is high and Q = 1 for the selected battery. Q0 = S0 and Q1 = S1 are the same wires.

Working

  1. Availability and health signals are provided for each battery.
  2. 7408 #1 AND gates generate V1–V4.
  3. The 74LS90 state (S1S0) names the priority battery: 00 = B1 … 11 = B4.
  4. S1,S0 select one of V1–V4 through the 74LS153.
  5. The MUX output Y is applied to the D input of the 74LS74.
  6. On CLK↑ the flip-flop stores the selected validity: Q = VALID.
  7. The 74LS155 (1G̅ = Q̅, 1C = CLK) drives the matching active-LOW EN output only for a valid battery, while the clock is high. The 74LS139 indicates the selected position.
  8. When the swap is completed the user presses SWAP_DONE; 7408 #2 forms CNT_CLK = VALID · SWAP_DONE.
  9. When SWAP_DONE is released, CNT_CLK falls and the 74LS90 advances: the next battery becomes the priority battery.
  10. If VALID = 0, CNT_CLK stays 0 and the counter waits on that battery (no skipping).

74LS90 as MOD-4: CNT_CLK → CKA, QA → CKB, R0(1) = R0(2) = QC, R9(1) = R9(2) = GND. Q0 = QA, Q1 = QB. When QC would become 1 the counter is reset, so only states 00–11 occur. Other tie-offs: 74LS153 1G̅ = GND, 74LS74 PRE̅ = CLR̅ = +5V, 74LS139 1G̅ = GND.

Advantages

  • Health- and availability-aware enable
  • Round-robin priority that advances only after a completed swap
  • Simple digital logic, easy to simulate
  • Shows combinational + sequential logic and a clock
  • Extendable to more batteries

Applications

  • EV battery swapping stations
  • E-scooter / e-rickshaw battery swap kiosks
  • Battery banks and charging racks (educational model)

Limitations

  • Binary A/H inputs only; no real SOC/SOH measurement.
  • The counter waits on an invalid battery (CNT_CLK = 0): there is no skipping, so one bad battery blocks the sequence until fixed or RESET.
  • Stale-Q hazard: releasing SWAP_DONE while CLK is high can briefly enable the next battery.
  • Small gate-delay glitches at clock edges are not modelled.
  • Real systems need a BMS, sensors, isolation and power electronics. This is a logic prototype.

Future Scope

  • Future Enhancement: automatic skipping of invalid batteries (priority encoder or search logic).
  • Real SOC/SOH inputs via ADC and comparators.
  • 8 batteries: 3-bit counter, 74LS151, 3-to-8 decoder.

Conclusion

The controller validates each battery with AND gates, checks the priority battery, latches the result, issues an active-LOW enable only for a valid battery, and moves to the next battery only after SWAP_DONE. Its limits are stated openly.
