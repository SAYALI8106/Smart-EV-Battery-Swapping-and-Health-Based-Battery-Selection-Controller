Problem Statement & Motivation

An EV battery swapping station holds several batteries, but some may be unavailable or unhealthy. The controller turns “available” and “healthy” into one valid bit per battery, checks the batteries one after another, and only enables a battery that is valid.

Motivation: handing a customer a battery that is not ready or not healthy wastes time and is unsafe.

Novelty

Combines validity checking, round-robin selection, latching, automatic skipping of bad batteries and active-LOW enable generation in a small educational logic design. It is a model, not a production EV technology.

Problem Understanding & Requirements

  • Four EV batteries, each with Availability (A) and Health (H).
  • A battery is valid only when A = 1 and H = 1.
  • Batteries are checked in round-robin order (MOD-4 counter + 4:1 MUX).
  • A D flip-flop stores the selected validity; a demultiplexer generates the enable.
  • A valid battery stays selected until SWAP_DONE is pressed; then the counter moves on.
  • An invalid battery is skipped automatically at the next clock fall.
  • A decoder indicates the selected battery position.
How skipping is done (honest note): the 74LS153 and 74LS90 alone cannot skip. Skipping comes from added gates: CNT_CLK = Q·SWAP_DONE + Q̅·CLK. When the latched battery is invalid (Q̅ = 1) the clock passes through the 7408 AND gate #2 and the 74LS32 OR gate, so the counter advances by itself. One extra 74LS32 OR gate is needed.

Q is the latched validity of the battery the counter pointed at when the clock rose.

CNT_CLK = Q·SWAP_DONE + Q̅·CLK

The 74LS90 counts on the falling edge of CNT_CLK. Valid battery (Q = 1): CNT_CLK follows SWAP_DONE, so it advances when SWAP_DONE is released. Invalid battery (Q = 0): CNT_CLK follows CLK, so it advances at CLK↓ and the battery is skipped.

Enable path (as implemented)

1G̅ = Q̅ 1C = CLKENn = NOT( CLK · Q · [S1S0 = n−1] )

Q̅ drives the active-LOW 1G̅ (enabled when valid) and the clock drives 1C, so the selected output is LOW only while the clock is high. An invalid battery (Q = 0) never produces an EN.

Known hazard: if SWAP_DONE is released while CLK is high, the counter moves while the old Q = 1 is still stored, so the new battery's EN can be LOW until CLK falls. Release SWAP_DONE while CLK is low. The skip path has no such problem because Q = 0 then. Gate-delay glitches (e.g. Q̅·CLK at the CLK↑ instant) are ignored in this ideal model; a real build would register the skip signal.

State Table

Valid battery: stays until SWAP_DONE, then next. Invalid battery: next state at the next CLK↓ (skip). The sequence stays B1 → B2 → B3 → B4 → B1.

State Diagram

Timing Diagram (5 clock cycles from RESET, current switches)

Each clock cycle is four slots. CLK↑ latches Q. Valid (Q = 1): SWAP_DONE pressed in slot 2; on release CNT_CLK falls and the counter advances. Invalid (Q = 0): CNT_CLK follows CLK (Q̅·CLK), and when CLK falls the counter advances: the battery is skipped, with no EN. EN rows are LOW (shaded) only while CLK is high and Q = 1 for the selected battery. Q0 = S0, Q1 = S1.

Working

  1. Availability and health signals are provided for each battery.
  2. 7408 #1 AND gates generate V1–V4.
  3. The 74LS90 state (S1S0) names the battery being checked: 00 = B1 … 11 = B4.
  4. S1,S0 select one of V1–V4 through the 74LS153; Y goes to D of the 74LS74.
  5. On CLK↑ the flip-flop stores the validity: Q = VALID, Q̅ = NOT VALID.
  6. Valid battery: 74LS155 (1G̅ = Q̅, 1C = CLK) drives the matching active-LOW EN while the clock is high. When the swap is done, the user presses SWAP_DONE; Q·SW = 1; on release CNT_CLK falls and the counter moves to the next battery.
  7. Invalid battery: Q = 0, so no EN. Q̅ = 1 lets the clock through 7408 #2 (Q̅·CLK) and the 74LS32 OR gate, so CNT_CLK falls at CLK↓ and the counter moves on to the next battery automatically.
  8. If every battery is invalid the counter keeps cycling B1…B4 and no EN is ever generated.

74LS90 as MOD-4: CNT_CLK → CKA, QA → CKB, R0(1) = R0(2) = QC, R9(1) = R9(2) = GND. Q0 = QA, Q1 = QB. Other tie-offs: 74LS153 1G̅ = GND, 74LS74 PRE̅ = CLR̅ = +5V, 74LS139 1G̅ = GND.

Advantages

  • Health- and availability-aware enable
  • Round-robin order; bad batteries are skipped automatically
  • A valid battery waits for SWAP_DONE before moving on
  • Simple digital logic, easy to simulate
  • Extendable to more batteries

Applications

  • EV battery swapping stations
  • E-scooter / e-rickshaw swap kiosks
  • Battery racks (educational model)

Limitations

  • Binary A/H inputs only; no real SOC/SOH measurement.
  • The 74LS153 + 74LS90 alone cannot skip; skipping needs the extra Q̅·CLK AND gate and 74LS32 OR gate.
  • If all batteries are invalid the counter cycles forever with no EN.
  • Stale-Q hazard when SWAP_DONE is released while CLK is high.
  • Gate-delay glitches are not modelled.
  • Real systems need a BMS, sensors, isolation and power electronics. This is a logic prototype.

Future Scope

  • Register the skip signal to remove glitch risk.
  • Real SOC/SOH inputs via ADC and comparators.
  • 8 batteries: 3-bit counter, 74LS151, 3-to-8 decoder.

Conclusion

The controller validates each battery, latches the result, enables only a valid battery, skips invalid ones and moves past a valid one after SWAP_DONE. Its limits are stated openly.
